# Pet Camera

**余っているスマートフォンを、ペットカメラ／見守りカメラにする。**

スマホをカメラとして部屋に置き、PCや別のスマホのブラウザから様子を見る。
カメラのON/OFFも手元から操作できる。外出先からも見られる。

- 見る側に専用アプリは要らない（ブラウザだけ）
- カメラ側にも専用アプリは要らない（ブラウザでページを開くだけ）
- 映像はサーバを経由せず端末同士が直接やりとりするので、遅延が小さく、PCの負荷もほぼゼロ
- 無料。クラウドサービスも契約も不要

---

## できること

| | |
|---|---|
| ライブ映像 | 遅延0.1〜0.3秒。1080pまで対応 |
| 音声 | 部屋の音を一緒に送る（既定はオフ） |
| 遠隔ON/OFF | 手元からカメラを止める・動かす |
| スナップショット | 見ている画面を静止画で保存 |
| 呼び出し音 | カメラ端末のスピーカーから音を鳴らす（3種類・音量2段階・手元で試聴可） |
| 画質切替 | 標準 / 省電力 |
| カメラ切替 | 背面 / 前面 |
| 画面消灯 | カメラ端末の画面を消したまま配信を続ける |
| 自動復帰 | 映像が止まっても10秒ほどで自動的につなぎ直す |
| 自動スタンバイ | 誰も見ていないときはカメラを止めて節電する |
| ズーム | カメラ側で寄せるので、拡大しても粗くならない（対応機種のみ） |
| 自動起動 | パソコンのログイン時に自動で立ち上げる |
| 見張り | トイレやエサ場など、決めた場所に猫がいるかを見る |
| 外出先から | Tailscale を使って、自宅を公開せずに外から見る |

---

## 必要なもの

- **カメラにするスマートフォン**（Android推奨。Chromeが動けばよい）
- **PC**（Windows / macOS / Linux）。サーバ役。動かしている間だけ映像を見られる
- 両方が同じWi-Fiにつながっていること

Androidを推奨するのは、iPhoneをカメラにすると画面ロックやアプリ切替で
カメラが止まる制約が強いため。見る側はiPhoneでも問題ない。

## 1. サーバを動かす（PC側）

### Windows

**`start.bat` をダブルクリックするだけ。**
必要な部品は自動で入る。Pythonが無ければその場で案内が出る。

### macOS / Linux

```bash
pip install -r requirements.txt
python server.py
```

Python 3.10以上が要る。入るのは `Flask` `simple-websocket` `cryptography` の3つ。

黒い画面に、**PIN** と **アクセスするアドレス** が表示される。

```
============================================================
  PET CAMERA サーバを起動しました
============================================================
  PIN            : 123456

  スマホ（カメラ）: https://192.168.x.x:8443/camera
  PC（視聴）      : https://192.168.x.x:8443/viewer
============================================================
```

**この黒い画面は閉じない。** 閉じるとカメラも止まる。

PINは初回起動時にランダムで作られ、`config.json` に保存される。
コードには書かれていない。変えたいときは `config.json` の `pin` を
書き換えて起動し直す（何桁でもよい）。

初回はOSがネットワークの許可を聞いてくる。
Windowsなら **「プライベートネットワーク」にチェックを入れて許可**。
許可しないとスマホからPCに届かない。

## 2. カメラにするスマホを設定する

1. スマホを**PCと同じWi-Fi**につなぐ（ゲストネットワークは不可。端末同士の通信が遮断されている）
2. Chromeで、表示されたアドレスの `/camera` を開く
3. 「接続はプライベートではありません」と警告が出る
   → **詳細設定 → 安全でないページに移動**
   （自分のPCが発行した証明書なので、この警告は想定どおり。
   　外出先対応をすると出なくなる）
4. PINを入力する
5. **CAMERA ON を押して、カメラの使用を許可する**
6. スマホをペットの見える場所に置き、電源につなぐ

**カメラの許可は最初の1回だけ。** 以後は見る側から遠隔でON/OFFできる。

### 設置するときの設定

常設で問題になるのは発熱と電池。効くものだけ挙げる。

| 設定 | 理由 |
|---|---|
| 電源につなぐ | 必須 |
| 画面の明るさを最低にする | 発熱と電力の主因 |
| ケースを外す・直射日光を避ける | 放熱 |
| 画面の自動回転をオフ | 置き方が変わって映像が回るのを防ぐ |
| 通知・着信を切る | 着信画面がページを覆うとカメラが止まる |
| Chromeのタブを1つだけにする | 他タブに切り替わると止まる |

何台からでも同時に見られる。

## 4. 外出先から見る（任意）

同じWi-Fiの外から見たい場合。**自宅をインターネットに公開せずに済む方法**を使う。

### Tailscale を入れる

[Tailscale](https://tailscale.com/) は、自分の端末同士だけを繋ぐ無料のサービス。
自宅のネットワークを外部に晒さない。

1. **PC**、**カメラのスマホ**、**見る端末**の3つにTailscaleを入れ、同じアカウントでログインする
2. 管理画面の **DNS → HTTPS Certificates** を有効にする
3. サーバを起動し直す

これだけで、サーバが自動的に正式なHTTPS証明書を取得し、
`https://端末名.ネットワーク名.ts.net:8443/` というアドレスで
**家でも外でも同じURL**、**証明書の警告なし**で使えるようになる。

証明書は90日で切れるが、期限が近づくと自動で取り直す。
サーバを止める必要はない。

### 注意

- **カメラのスマホにもTailscaleを入れること。** 入れ忘れると、
  状態表示は出るのに映像だけ来ない、という状態になる
- Androidでは **Tailscaleをバッテリー最適化の対象外にする**
  （設定 → アプリ → Tailscale → バッテリー → 制限なし）。
  そうしないとOSがVPNを勝手に切る
- 見る側の端末にもTailscaleが要る。家族に見せるなら招待リンクを送る。
  作り方は次のとおり（2分）:

  1. [login.tailscale.com](https://login.tailscale.com/) を開く
  2. 左メニューの **Users**
  3. **Invite external users** を押す
  4. **Copy invite link** のタブを選ぶ
  5. 権限（user role）は **Member** でよい
  6. **Generate & copy invite link** を押す

  **相手側に事前準備は要らない。** TailscaleにはID/パスワードが存在せず、
  Apple・Google・Microsoft・GitHub のいずれか、**すでに持っているアカウント**で
  サインインすると、その場で登録まで完了する。
  iPhoneユーザーなら Apple ID をそのまま使える。
  こちらのアカウント情報を渡す必要はない。

  `docs/iphone_setup_template.md` を一緒に渡すと、相手側の手順が済む。

## 画面の見かた

| 表示 | 意味 |
|---|---|
| DEVICE ONLINE | カメラ端末がサーバに繋がっている |
| DEVICE OFFLINE | カメラ端末が切れている |
| CAMERA ON | カメラが動いていて映像が流れている |
| CAMERA OFF | カメラは止まっている |
| CAMERA ERROR | カメラを起動できなかった。理由が画面に出る |

**DEVICE ONLINE なのに映像が来ない場合**、カメラ端末までは繋がっているが
映像の直接接続だけが失敗している。外出先からのときは
「カメラのスマホがTailscaleに入っていない」が最も多い原因。

### 映像が止まったとき

見る側は、映像が実際に進んでいるかを2秒ごとに見張っている。
8秒進まなければ壊れたと判断し、カメラ側へ作り直しを頼む。
**10秒ほどで自動的に戻るので、ページを開き直す必要はない。**

通信が一瞬切れただけで映像そのものが生きている場合は、あえて作り直さない。

## カメラ端末から音を鳴らす

見る側の「♪ 音を鳴らす」を押すと、**カメラを置いた端末のスピーカーから音が出る。**
ペットや子どもの反応を見たいときに使う。

| 音 | 内容 | 音域 / 細かさ |
|---|---|---|
| チャイム | やわらかい下降3音を2回。最後を長く響かせる。既定 | 高め / ふつう |
| 呼びかけ | 同じ高さを速く3回。気づいてほしいとき | 中 / 細かい |
| メロディ | 上って下りて最後に高く伸びる5音 | 広い / ゆるやか |

3つは**音の高さと間隔の細かさをずらしてある**ので、鳴った音で区別できる。

音量は 小 / 大 の2段階（大はかなり大きい）。音の種類も音量も**見る側で選ぶ**（カメラ端末を
触りに行く必要はない）。選択は端末に記憶される。

**音の種類を選ぶと、その場で手元で試聴できる。**
向こうの部屋に鳴らしてみるまで音が分からない、という状態にはしていない。

音源ファイルは持たず、その場で合成している（`static/sounds.js`）。
立ち上がりと消え際をなだらかにしてあるので、同じ音量でも驚かせにくい。

連打しても**1.5秒に1回までしか鳴らない**。相手のいる部屋なので、鳴らしすぎは害になる。

音が重なっても割れないよう、出口で軽く圧縮をかけている。

### 鳴らないとき

- **「カメラ端末が古い画面です」と出たら、カメラ端末のページを再読み込みする。**
  カメラ側の画面が古いと、新しく増えた音を知らない。
  知らない音を受け取っても**別の音に差し替えたりはしない**（選んだ音と違う音が
  鳴るのが、いちばん原因の分かりにくい壊れ方になるため）


- **カメラ端末の音量が下がっていないか。** メディア音量を上げておくこと
- 「カメラ端末の画面を一度タップしてください」と出た場合、
  ブラウザが「一度も触られていないページ」に音を出させない決まりのため。
  カメラ端末の画面を1回タップすれば、以後は遠隔で鳴らせる
  （設置時に CAMERA ON を押していれば、通常この状態にはならない）

## 節電

### 画面消灯

カメラ端末は、**触らずに1分たつと画面が真っ暗になる。配信は止まらない。**
映像のプレビューを描き続けるのが発熱と電力の主因なので、描画だけをやめている。
タップで戻る。すぐ消したいときは「画面を消す」ボタン。

消えている間も小さく「● 配信中」と出る。

### 自動スタンバイ

**誰も見ていない状態が1分続くと、カメラを止める。**
見る画面を開くと1〜3秒で自動的に起き上がる。
既定で有効。見る側の画面から切り替えられる。

「見ている」の判定は、画面が手前にあるかどうかで行う。
ページを開いたまま裏に回している場合は、見ていない扱いになる。

止めるまでの時間は `config.json` の `standby_after_sec`（既定60秒）で変えられる。

**スタンバイ中も画面のスリープ止めは解除しない。**
画面が消えるとページごと止められ、手元から起こせなくなるため。
撮影・圧縮・描画を止めるだけでも、消費の大部分は落ちる。

### ズーム

見る側の `−／リセット／＋` でカメラ側のズームを操作する。
**カメラ側で寄せるので、見る側で引き伸ばすより映像が精細になる。**

対応しているかは機種による。非対応なら、その旨が画面に出る。

### 画質

| | 解像度 | フレームレート |
|---|---|---|
| 標準 | 1280×720 | 24fps |
| 省電力 | 640×480 | 15fps |

長時間の見守りなら省電力を推奨。選んだ設定は端末に記憶される。

## 電池を持たせる

カメラ端末の電池残量と充電状況は、見る側の画面に出る。
**充電が外れていても気づけない**のが常設の弱点なので、常に見えるようにしてある。

効く順に並べると次のとおり。

| 手当て | 効き方 |
|---|---|
| **自動スタンバイ** | 誰も見ていないときカメラごと止める。いちばん大きい |
| **見ていない相手へは送らない** | 画面を裏に回している相手への送信を止める。映像は相手ごとに別々に圧縮しているので、圧縮の手間も電波もまるごと減る |
| **見張り中の自動減量** | 見張りだけのときは 320×240 / 5fps まで落とす。見に来たら戻す |
| **送信量の上限** | 標準1.2Mbps / 省電力500kbps / 見張り150kbps。決めないとブラウザが勝手に高く取る |
| **画面消灯** | 映像の描画をやめる（1分無操作で自動）。消していても見張りは動く |
| **省電力画質** | 640×480 / 15fps |
| 画面の明るさを最低にする | 端末側の設定。効果は大きい |

送信を止めた相手が見に戻ったとき、粗い絵から徐々に戻るのを避けるため、
帯域が足りないときは解像度ではなくコマ数を落とす設定にしてある。

### 効果の測りかた

見る側の画面に、カメラ端末の電池残量と充電状況が出る。
設定を変えて1時間ほど放置し、減り方を比べれば効果が分かる。

### 越えられない壁

**画面を点けたままにする必要がある。**
ブラウザで動かしている以上、画面が消えるとページごと止められ、
カメラも遠隔操作も止まる。この分の消費は、この作りでは避けられない。

本当に電池を切り詰めたい場合は、カメラ側を Android アプリにするしかない。
アプリなら画面を消したまま動かせる。
そのときもサーバと見る側の画面はそのまま使える。

### 充電が追いつかないとき

**充電器を疑うこと。** 消費が 3〜4W あるので、
5V/1A（5W）の古い充電器では追いつかず、つないでいるのに減っていく。
5V/2A 以上のものに替えると解決することが多い。

## パソコンの起動時に自動で立ち上げる

`install_autostart.bat` をダブルクリックする。それだけ。

- ログインすると自動で使える状態になる
- **黒い画面は出ない**
- 落ちても1分後に起動し直す

「アクセスが拒否されました」と出たら、右クリック →「管理者として実行」。

黒い画面が出ないぶん、状態とアドレスは **`status.bat`** で確認する。
止めたいときは `stop.bat`、やめたいときは `uninstall_autostart.bat`。

### 起動直後の証明書について

パソコンの電源を入れた直後は、Tailscale がまだ立ち上がっていないことがある。
そのときは**いったん自己署名の証明書で動き始め、用意ができ次第、
サーバを止めずに正式なものへ差し替える**。利用者の操作は要らない。

## 決めた場所を見張る（試験中）

ケージの「トイレ」「エサ場」のように、映像の中の決まった場所を見張り、
**そこに猫がいるかどうか**を判定する。

見る側の画面で `トイレの範囲` `エサ場の範囲` を押し、映像の上をなぞって囲む。
`見張り` を「する」にすると、反応値がリアルタイムで出る。

### 使う前に「普通の景色」を覚えさせる

見張りは**覚えた景色との違い**を見ている。
覚えたときに猫が写っていると、**判定が逆になる**（いるのが普通、いないと反応する）。

そのため、**猫がいない状態で「いまの景色を覚え直す」を押す**こと。
これを忘れると、いくら待っても反応値が 0 のままになる。

「検知が見ているもの」に、変わったと判断した点が橙色で出る。
猫がいるのに塗られないなら、覚え直しが要るというサイン。

### 数字の意味

**その範囲の何%が変わったか**（0〜100）。
範囲の半分を猫が占めていれば 50 前後になる。

平均の差ではなく割合にしているのは、広い範囲に小さな猫がいても
薄まって埋もれないようにするため。

### 猫を見分けるのではない

画像認識で猫を探すのではなく、**「そこに何かいる」を見ている。**
カメラは固定でケージの中で動くのは猫だけなので、実用上これで足りる。
画像認識より、はるかに軽く、暗いところでも粘る。
（手を入れても掃除をしても反応する、という性質はある）

### 動きではなく「いる」を見る

前のコマとの差分ではなく、**誰もいないときの背景との差**を見ている。
差分方式だと、トイレでじっとしている猫を見逃す。
用を足している間はほとんど動かないので、そこが取れないと意味がない。

背景は照明の変化に合わせて少しずつ覚え直すが、
**「いる」と判定している区画だけは覚え直さない。**
そこを更新すると、居座っている猫が背景に溶けて見えなくなる。

### 自動スタンバイとは両立しない

見張りは24時間カメラを動かし続ける必要があり、自動スタンバイは正反対の機能。
**見張りを入にすると、自動スタンバイは自動的に止まる**（切ると元に戻る）。

### いまの段階

**反応値を見るところまで。** 録画も通知もまだ入れていない。
実際の設置場所で、猫がいるとき・いないとき・夜間にどんな値が出るかを
確かめてから、しきい値と録画を作る。

## セキュリティ

- PINを知らないと、映像も操作画面も見られない
- PINはコードに書かれていない。初回起動時にランダム生成され `config.json` に入る
- **PINを5回続けて間違えると、そのIPを5分締め出す**（繰り返すと最大1時間）
- 通信はすべてHTTPSで暗号化。映像もWebRTCの規格で暗号化される
- Tailscaleを使う構成では、**自宅はインターネットに公開されない**

`config.json` と `certs/` は秘密なので、**gitに含めないこと**（`.gitignore`済み）。

## うまくいかないとき

**スマホでページが開かない**
- PCとスマホが同じWi-Fiか。ゲストネットワークではないか
- OSのファイアウォールで許可し忘れていないか

**カメラが起動しない / ERROR になる**
- ブラウザのアドレスバー左のアイコンからカメラを「許可」にする
- 他のアプリがカメラを使っていると起動できない

**CAMERA ON なのに映像が黒いまま**
- カメラ端末が他のアプリに切り替わっていないか、画面が消えていないか
- 外出先からの場合、カメラ端末がTailscaleに繋がっているか
- iPhoneで「タップして再生」と出たら、映像部分を1回タップする

**ページを直したのに表示が変わらない**
- サーバが二重に起動している可能性がある。黒い画面をすべて閉じてから
  起動し直す（二重起動は検出して止まるようにしてある）

**黒い画面が固まって、どこからも繋がらなくなった**
- Windowsのコンソールは、クリックすると出力が止まりプログラムごと停止する。
  対策済みだが、古い版では起きる。文字をコピーしたいときは
  右クリック → 編集 → 範囲指定 を使う
- 通信の記録は画面ではなく `petcam.log` に書いているので、
  画面側で何が起きてもカメラは動き続ける

## 仕組み

```
   カメラのスマホ                    見る端末
        │                              │
        │  ←──── 映像は直接 ────→      │   WebRTC
        │                              │
        └──────────┬───────────────────┘
                   │
              server.py
      （引き合わせと状態の通知だけ）
```

映像は**サーバを通らず、端末同士が直接やりとりする**（WebRTC）。
サーバがするのは、お互いを引き合わせることと状態を伝えることだけ。

そのおかげで、

- 遅延が小さい（0.1〜0.3秒）
- サーバのCPUをほとんど使わない
- スマホは映像の圧縮に専用の回路を使うので、発熱と電池の減りが抑えられる

外出先から見るとき、映像はインターネット経由の直接接続になる
（`config.json` の `ice_servers` に設定したSTUNサーバで経路を見つける。
STUNは「自分が外からどう見えるか」を答えるだけで、映像は通らない。
不要なら `[]` にできる）。

## 開発者向け

### 壊していないか確かめる

```bash
python selftest.py
```

認証・締め出し・状態通知・遠隔操作・つなぎ直し・シグナリング中継を確認する。
映像そのものは実機でしか確かめられない。

### 画面を直すとき

```bash
python server.py --http --port 8444
```

このPCの中だけで `http://127.0.0.1:8444/` として動く。
`localhost` はHTTPでもブラウザが安全な文脈として扱うのでカメラが開ける。
証明書の警告を抜ける手間がない。本番を止めずに試せる。

`templates/` と `static/` の変更は、ページを再読み込みすれば反映される
（サーバの再起動は不要）。

### 映像がつながらないときの調べかた

両端がどんな経路の候補を出し合ったかが `petcam.log` に残る。

```
[診断 camera/xxxxxx] 自分の候補 host udp 192.168.0.13 51234
[診断 viewer/yyyyyy] 自分の候補 srflx udp 122.133.x.x 49067
[診断 viewer/yyyyyy] 採用された経路 自分[srflx 122.133.x.x] -> 相手[prflx ?]
```

`採用された経路` が出ていれば接続は成立している。
出ないまま `ICE failed` が続く場合は、候補が足りていない。
